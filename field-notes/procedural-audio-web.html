The math behind procedural audio on the web

Why visual interactions become more tactile when sound is generated from the same gesture—not pasted on afterwards.

Hear it in Aether

A recording can react to a click. A synthesizer can react to the shape, speed, direction, and duration of the gesture itself.

Moving past static MP3 assets

The easiest way to add sound to a website is to play a file:

new Audio("/sounds/interaction.mp3").play();

For a notification, that may be exactly right. For a continuous instrument such as AETHER, it becomes restrictive. A recording has a fixed pitch, duration, envelope, and spectral character. It can be restarted or layered, but it cannot truly inherit the geometry of a live gesture.

The Web Audio API provides oscillators, filters, gain stages, analysers, delays, convolvers, and compressors as nodes in a signal graph. Instead of choosing which sound file to play, the interface generates a sound whose parameters evolve alongside its visuals.

Constructing the synthesis tree

A simplified AETHER voice uses this path:

Oscillator -> Low-pass filter -> Gain envelope -> Compressor -> Output 
const context = new AudioContext();

const oscillator = new OscillatorNode(context, {
  type: "sine",
  frequency: 110
});

const filter = new BiquadFilterNode(context, {
  type: "lowpass",
  frequency: 900,
  Q: 4
});

const gain = new GainNode(context, {
  gain: 0
});

const compressor = new DynamicsCompressorNode(context, {
  threshold: -18,
  knee: 12,
  ratio: 5,
  attack: 0.003,
  release: 0.18
});

oscillator
  .connect(filter)
  .connect(gain)
  .connect(compressor)
  .connect(context.destination);

oscillator.start();

The oscillator can run continuously while the gain envelope decides when it is audible. The filter determines brightness. The compressor catches exceptional peaks, but it is a safety layer—not a substitute for sensible gain staging.

Browsers require audio to begin after a deliberate user gesture. That restriction is also good interface etiquette: 

startButton.addEventListener("click", async () => {
  await context.resume();
});

Sound should be invited, never smuggled into the page load.

Converting cursor movement into a signal

Consecutive pointer positions produce a velocity vector v = (vx, vy). Its magnitude describes speed:

|v| = √(vx² + vy²)
θ = atan2(vy, vx) 
const vx = pointer.x - previousPointer.x;
const vy = pointer.y - previousPointer.y;

const speed = Math.hypot(vx, vy);
const direction = Math.atan2(vy, vx);

Raw pointer values are noisy and device-dependent. A trackpad can emit a different cadence than a mouse or touchscreen, so I normalize and smooth the velocity before it reaches the synthesis graph. 

const normalizedSpeed = Math.min(speed / 60, 1);

smoothedSpeed +=
  (normalizedSpeed - smoothedSpeed) * 0.12;

This one-pole smoothing filter removes abrupt jumps without introducing enough latency to disconnect sound from motion.

Mapping velocity to perceived pitch

Human pitch perception is approximately logarithmic. Doubling a frequency raises it by one octave, so a linear mapping from speed to hertz bunches most of the perceptual change near the upper end. 

const minimumFrequency = 82.41;
const octaveRange = 3;

const frequency =
  minimumFrequency *
  2 ** (smoothedSpeed * octaveRange);

This moves smoothly from roughly 82 Hz to 659 Hz. Direction can contribute a smaller pitch displacement: 

const directionalOffset =
  Math.sin(direction) * 35;

const targetFrequency =
  frequency + directionalOffset;

Assigning that value directly would create discontinuities. Audio parameters should be scheduled: 

oscillator.frequency.setTargetAtTime(
  targetFrequency,
  context.currentTime,
  0.025
);

setTargetAtTime() produces a short exponential approach and prevents the zipper-like artefacts caused by abrupt parameter updates.

Using speed to control spectral brightness

A low-pass filter removes frequencies above its cutoff. Opening that filter makes the sound brighter and more exposed, which maps naturally to visual energy. 

const minimumCutoff = 260;
const maximumCutoff = 7200;

const cutoff =
  minimumCutoff *
  (maximumCutoff / minimumCutoff)
    ** smoothedSpeed;

filter.frequency.setTargetAtTime(
  cutoff,
  context.currentTime,
  0.035
);

Slow movement produces a muted, rounded tone. Fast movement opens the filter and exposes more harmonic energy. Cursor velocity now increases both fluid turbulence and spectral brightness.

The visual and sonic systems do not need to describe each other. They need to share a cause.

ADSR envelopes without clicks or clipping

Rapid clicks and drags can create discontinuities in a waveform. Several voices can also overlap above a safe amplitude. A gain envelope shapes each event through attack, decay, sustain, and release. 

function triggerEnvelope(gainNode, velocity = 1) {
  const now = context.currentTime;
  const peak = 0.18 * velocity;
  const sustain = peak * 0.45;

  gainNode.gain.cancelScheduledValues(now);
  gainNode.gain.setValueAtTime(
    gainNode.gain.value,
    now
  );

  gainNode.gain.linearRampToValueAtTime(
    peak,
    now + 0.015
  );

  gainNode.gain.exponentialRampToValueAtTime(
    Math.max(sustain, 0.0001),
    now + 0.12
  );
}

Releasing the gesture schedules a short fade:

function releaseEnvelope(gainNode) {
  const now = context.currentTime;

  gainNode.gain.cancelScheduledValues(now);
  gainNode.gain.setValueAtTime(
    Math.max(gainNode.gain.value, 0.0001),
    now
  );

  gainNode.gain.exponentialRampToValueAtTime(
    0.0001,
    now + 0.28
  );
}

Cancelling old schedules is essential. Otherwise, fast gestures leave behind a queue of stale gain changes that continue after the interaction has moved elsewhere. Exponential ramps cannot reach literal zero, hence the small positive floor.

Sound needs negative space

Procedural audio creates an obvious temptation: sonify everything. The result is usually fatigue rather than immersion.

I treat sound like visual contrast. Silence is negative space. A sustained tone has weight. A short transient behaves like punctuation. Brightness indicates energy while pitch can suggest height or direction.

The interface needs an immediate mute control, an honest active-state indicator, and conservative gain levels. Reduced-motion preferences can also reduce aggressive modulation, even though visual and auditory sensitivities are not identical.

Synesthesia through shared causality

Synesthesia in browser design does not mean assigning arbitrary notes to colours. It means connecting modalities through the same underlying variables.

  • Pointer speed affects fluid force and filter cutoff.
  • Vertical position influences colour placement and pitch.
  • Gesture duration shapes both fluid persistence and the gain envelope.
  • Dissipation informs the sonic release time.

The eye and ear receive different output, but both explain the same action. That agreement makes the interaction tactile. The visitor is no longer moving a cursor while background audio happens to play. They are performing an instrument whose body is made from pixels.

Once movement has sound, timing becomes physical. Once sound follows velocity, a gesture gains texture. When sight and hearing respond coherently, the experience becomes much harder to forget.
